# D31 财务语义校验设计

用户已批准两条线并行：复查 D27 连接；开展财务类型、真实表头列归属、结构规则/模型对照和新公司评估。本设计落实该授权，常规工程与人工审核并行，不再重复要求同一方向批准。

## 方法选择

采用可审计的表格结构约束＋固定 Qwen 复核。相对于继续单纯提示词优化，它把金额/比率/每股、当期/上期/调整前后、原始单位作为明确来源属性。不同于重新训练或换大模型，它可在现有小样本下检验各部分贡献，不需要付费接口或新增模型。采用原 Python/React 栈及已有独立研究环境，不改变冻结 D29/D30 源码。

使用公开 PDF 的字词位置或可靠的明确表头布局建立行、列、表头关联，不以“第一数字就是当期”代替识别。不确定/冲突/跨页无表头的候选保留并标明待核，不靠参考答案剪裁。每个来源候选须保存原行、物理页、值位置、表头/单位证据、财务类型、期间角色、调整角色及可用/排除原因。金额继续 Decimal 字符串，百分比/每股不能伪装为金额。期间与合并范围仍是查询约束；范围证据不足须披露，不能声称已独立理解全报告口径。

## 对照与冻结

新模块 research/filing_semantics，产物 research/artifacts/filing-semantics，只读发布 backend/data/filing-semantics。固定原三公司2024Q1×三字段9项开发；旧2025已看过的样本不当新评估。两方法共享相同公开结构输入：结构规则在唯一一致的合格金额时回答，否则拒答；结构规则＋模型只能在合格来源候选与拒答中选择（同字段同键序的前缀树）。结构保障不计作 AI 语义增益，模型未改善也照实记录。

模型保持 Qwen/Qwen2.5-1.5B-Instruct revision 989aa7980e4cf806f80c7fef2b1adb7bc71aa306，CUDA BF16、batch1、seed0、greedy、输入4096/输出384token、引用160字符。不截断过长输入；候选/表格预算溢出阻塞，不静默丢弃。保存完整提示词、原始输出/token和选项。开发变更需新 attempt/协议，旧输出不覆盖。

测试包括交换当前/上期列、当前非首列、调整前后、单位元/万元/百万元/亿元/千元、负数/脚注、扣非及变动率、缺失/冲突表头、重复不同值、跨页无继承、坏JSON、拒答和预测后篡改。记录格式、回答/拒答、金额、原单位、证据、完整正确及候选覆盖；检查 D30 四个错误的拦截原因。变形测试是工程挑战集，不当独立真实样本或模型泛化成绩。

开发完成后冻结最终方法/配置/源码/模型资产身份与挑战集收据，写入 method-freeze。然后且仅然后启封已登记三公司000333/601318/600887各2025Q1，预定名单不随结果替换。核对正文证券代码、发行主体、报告期间/报告类型，保存身份核验、PDF SHA、原始提取与视觉页证据。参考由独立视觉核对制作，标为助手参考待人工审核，不能称专家金标。模型输入只用前6物理页；参考可用后页审计范围并明确上下文缺口。所有预测先封存，再由独立评分阶段读取参考。新公司阶段不再调整方法；不足/失败如实保留，若修正源码则另立下一轮开发，不能将该三家继续称未知样本。

## 界面与边界

训练评测页独立 D31 面板：开发/新公司分开，逐字段解释“为什么这是当期金额”、来源表头、排除原因、模型选择/拒答；格式与语义、规则贡献与模型贡献分开。只读 API 无训练/下载动作；GET 校验已冻结来源、原始预测、评分、身份与参考。保留旧 D30/D29 页面与成绩。沿用 Interactive-front-end 的反馈/键盘/窄屏/减少动态，导出 JSON/Markdown，错误不得显示陈旧成绩。

D27 仅运行一次原有有界管线；不修改其源码、模型、校准/来源，不清未知锁，不补记。旧账号、M1、FinQA 保留集禁读写边界不变，不部署/交易/付费。无破坏性数据库操作。
